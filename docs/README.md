## 四条主线

### 1. 我要做一款游戏

按这个顺序读：

1. [构建指南](build-guide.md) —— 先跑通「框架 jar → 内容项目 → 可玩产物」这条链路
2. [剧情开发指南](story-guide.md) —— 然后开始写章节
3. [数据键](data-keys.md) —— 需要存东西时再回来看

**贯穿始终的一条规则：不要改框架源码。**
你需要的扩展点都是预留好的（内容初始化入口、资源重定向、数据键注册、
插件与注入点）。改了框架就失去「框架可独立升级」这个前提。

### 2. 我要给框架加功能 / 修 bug

- 先看 [剧情开发指南](story-guide.md) 里「键空间规范」与相关章节，
  确认你要加的东西是不是应该属于内容而不是框架。
- 涉及数据结构（新增键、改键名、改默认值）时，
  [数据键](data-keys.md) 里有强制的注册规范。
- 改动插件 API、注入点语义或启动流程时，需要递增
  `GameConstants.FRAMEWORK_VERSION`。

### 3. 我想知道许可上有什么约束

[许可说明](licensing.md) —— 简短版：**不改框架代码，你的游戏就可以闭源**；
改了框架代码，改动部分要按 AGPL-3.0 开源。

### 4. 我想在某个时机插一脚

[生命周期事件](lifecycle-events.md) —— 框架在菜单显示、章节切换、存档、
设置开关等时机广播事件，**监听即可，不用改框架**；没人监听时广播是空操作。
内容与插件也可以用同一套机制广播自己的事件。

## 快速开始（框架自检）

框架不含任何游戏内容，单独运行会拒绝启动。想看它降级运行时长什么样：

```bat
gradlew.bat run --args="-no-admin -debug -no-content"
```

该模式下主菜单背景纯黑、字体回退系统字体、不播音频、用系统默认图标，
并且**禁止开始游戏** —— 它只是自检工具，不是可玩状态。
